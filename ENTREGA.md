# Checklist de entrega · Trilha Front-end · Opção B (Codificação)

Fonte: Roteiro de Atividade Prática rev 0.6 + Estudo de Caso rev 0.3.

## Entrega técnica (Opção B)
- [x] Código em HTML/CSS/JS puro ou framework (escolhido: React + TypeScript)
- [x] Dados mockados para cardápio e interações
- [ ] Link do repositório Git **público**
- [ ] URL de publicação (Vercel, Netlify ou GitHub Pages) **pública e funcional**
- [ ] Testar ambos os links em aba anônima antes de enviar (link inacessível = nota zero)
- [ ] O que está no app bate com o que está documentado no PDF

## Requisitos funcionais obrigatórios (ao menos conceitualmente)
- [x] Cadastro e autenticação de usuários
- [x] Cardápio por unidade (dinâmico)
- [x] Realização de pedidos
- [x] Acompanhamento do status do pedido
- [x] Programa de fidelização (pontos, descontos, benefícios) e recompensas
- [x] Promoções e campanhas
- [x] Solicitação de pagamento via serviço externo (fluxo de envio e retorno visual, sem pagamento real)
- [x] Conformidade explícita com LGPD

## Requisitos não funcionais obrigatórios
- [x] Mobile-first
- [x] Responsividade
- [x] Performance e escalabilidade da interface

## Multicanal
- [x] App, Totem e Web representados nos requisitos, fluxos e telas

## Documento PDF (arquivo único, `RU_Projeto_Front_End.pdf`)
- [ ] Capa: curso, disciplina, nome, RU, polo, semestre, professor
- [ ] Sumário
- [ ] Introdução: contexto, objetivos, usuários, relevância
- [ ] Análise e requisitos: RF e RNF (tabela, com justificativa e priorização)
- [ ] Diagrama de casos de uso com atores: Cliente, Atendente, Cozinha, Gerente/Administrador, Sistema de Pagamento Externo
- [ ] Descrição de feature (ex.: Realizar Pagamento): fluxo principal, pré-condições, processamento externo
- [ ] Diagrama da jornada do usuário: do cardápio até pagamento confirmado e retirada, com decisões, estados e integrações
- [x] Wireframes de baixa fidelidade, mobile e desktop, telas principais e fluxos
- [ ] LGPD na interface: avisos, consentimento, clareza no uso dos dados
- [ ] Entrega técnica: links do repositório e do deploy
- [x] Plano de testes: no mínimo 10 cenários (positivos e negativos), com entradas, passos, saídas esperadas e mensagens de erro; foco em usabilidade, responsividade e LGPD
- [x] Evidências (prints, relatórios de teste)
- [ ] Conclusão: integrações, impacto das decisões de interface, relação com back-end, QA e LGPD
- [ ] Referências (ABNT)
- [ ] Anexos opcionais: outros diagramas UML, prints

## Pontuação
| Critério | Pontos |
|---|---|
| Análise do problema e requisitos | 20 |
| Modelagem e arquitetura da interface | 20 |
| Wireframes / protótipos / interface | 25 |
| LGPD, qualidade e plano de testes | 15 |
| Entrega técnica | 10 |
| Documentação e postura profissional | 10 |

## Riscos de nota zero
- Links privados ou fora do ar na correção
- Similaridade com material de terceiros (inclusive os exemplos do anexo do roteiro)
